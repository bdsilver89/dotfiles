# Neovim Config — Full Implementation Plan (Phases 0–8)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> **DO NOT COMMIT THIS PLAN OR THE SPEC.** This repo takes config commits only. Task commits below cover `config/nvim/` files and are expected.

**Goal:** A `vim.pack`-based Neovim config with IDE depth — LSP for 5+ languages, treesitter, completion, navigation, git, GitHub, debugging, testing, linting, formatting, and database — holding startup under 80ms.

**Architecture:** `init.lua` names no plugins. Neovim auto-sources `plugin/*.lua`, one file per plugin, each registering a load trigger via `lua/pack.lua` and returning. Core modules in `lua/` never touch a plugin, so the config degrades to a working editor if `plugin/` is removed.

**Tech Stack:** Neovim 0.12.4, `vim.pack`, native `vim.lsp.config`/`vim.lsp.enable`, nvim-treesitter (main), blink.cmp, fzf-lua, nvim-dap, neotest.

**Spec:** `docs/superpowers/specs/2026-08-06-neovim-config-design.md`

**Working directory for all commands:** `/home/brian/dotfiles/config/nvim`

### Deviation to resolve

`treesitter.lua` currently lives in `lua/` and is pulled in by an explicit `require("treesitter")` in `init.lua`. The architecture calls for `plugin/treesitter.lua`, auto-sourced. Both work, but the `plugin/` form is the decision of record — it removes require bookkeeping from `init.lua` and makes disabling a plugin a file rename. Task 7 moves it.

### Resolved during implementation

Three findings changed the plan and are already folded into the tasks below:

1. **WSL2 clipboard was the startup key-latency cause**, not the statusline. `clipboard=unnamedplus` routed every yank through `win32yank.exe` across the `/mnt/c` interop boundary: **477 ms** on the first yank. Fixed with OSC52 for copy and win32yank for paste — **1.52 ms**, a ~310× improvement. The statusline was never implicated; it measures 0.0169 ms per full evaluation.
2. **Mason needs no plugin at startup.** Its binaries are plain symlinks in `mason/bin` that run standalone. The entire startup-time role is one `vim.env.PATH` append, so mason.nvim loads only behind `:Mason`/`:ToolSync`. The spec said *prepend*; it must **append**, so system-native `clangd` and `rust-analyzer` win over any mason copy.
3. **`rustaceanvim` has no `setup()`** — it configures via `vim.g.rustaceanvim`, so its spec needs `setup = false`.

In `lua/pack.lua`, add these two functions immediately after `local M = {}` and the `---@class` block:

```lua
--- Expand a spec `src` into a URL git can clone.
--- Bare `owner/repo` becomes a GitHub URL; anything already carrying a scheme
--- or an scp-style `host:path` is returned unchanged.
---@param src string
---@return string
function M.url(src)
  if src:match('^%a[%w+.%-]*://') or src:match('^[^/]+@[^/]+:') then
    return src
  end
  return 'https://github.com/' .. src
end

--- The module name to require() for a spec.
--- Defaults to the repository name with a trailing `.nvim` removed.
---@param spec PluginSpec
---@return string
function M.module_name(spec)
  if spec.module_name then
    return spec.module_name
  end
  local repo = spec.src:match('([^/:]+)$')
  return (repo:gsub('%.nvim$', ''))
end
```

Then rewrite `configure()` to use them, replacing the `sources` mapping and the inline `module_name` derivation:

```lua
local function configure(specs)
  local sources = vim.iter(specs)
    :map(function(spec)
      return { src = M.url(spec.src), name = spec.name, version = spec.version }
    end)
    :totable()

  vim.pack.add(sources, { confirm = false })

  for _, spec in ipairs(specs) do
    if spec.setup ~= false then
      local mod = require(M.module_name(spec))
      if type(mod.setup) == 'function' then
        local opts = spec.opts
        if type(opts) == 'function' then
          opts = opts()
        end
        mod.setup(opts or {})
      end
    end
    if spec.on_setup then
      spec.on_setup()
    end
  end
end
```

```lua
--- With laststatus=3 there is a single global statusline, so it can only show
--- one filename no matter how many windows are open. The winbar carries the
--- per-window identity.
local icons = require('icons')

local M = {}

---@return string
function M.render()
  -- Floating windows and special buffers get no winbar.
  if vim.api.nvim_win_get_config(0).relative ~= '' then
    return ''
  end
  if vim.bo.buftype ~= '' then
    return ''
  end

  local name = vim.fn.expand('%:.')
  if name == '' then
    return '%#WinBarNC#[No Name]%*'
  end

  local flags = ''
  if vim.bo.modified then
    flags = flags .. ' ' .. icons.misc.modified
  end
  if vim.bo.readonly then
    flags = flags .. ' ' .. icons.misc.readonly
  end

  return '%#WinBar#' .. name .. '%*' .. flags
end

vim.o.winbar = '%{%v:lua.require("winbar").render()%}'

return M
```

```lua
  ---@param mode? string|string[]

    vim.keymap.set(mode or 'n', lhs, rhs, { buffer = bufnr, desc = desc })

  map('gD', vim.lsp.buf.declaration, 'Go to declaration')
  map('gy', vim.lsp.buf.type_definition, 'Go to type definition')
  map('K', vim.lsp.buf.hover, 'Hover')

  map('[d', function()
    vim.diagnostic.jump({ count = -1 })
  end, 'Previous diagnostic')
  map(']d', function()
    vim.diagnostic.jump({ count = 1 })
  end, 'Next diagnostic')
  map('[e', function()
    vim.diagnostic.jump({ count = -1, severity = vim.diagnostic.severity.ERROR })
  end, 'Previous error')
  map(']e', function()
    vim.diagnostic.jump({ count = 1, severity = vim.diagnostic.severity.ERROR })
  end, 'Next error')
  map('<leader>cd', vim.diagnostic.open_float, 'Line diagnostics')

  if client:supports_method('textDocument/inlayHint') then
    map('<leader>ch', function()
      local on = vim.lsp.inlay_hint.is_enabled({ bufnr = bufnr })
      vim.lsp.inlay_hint.enable(not on, { bufnr = bufnr })
    end, 'Toggle inlay hints')
  end

  if client:supports_method('textDocument/documentHighlight') then
    local group = vim.api.nvim_create_augroup('config_lsp_hl_' .. bufnr, { clear = true })
    vim.api.nvim_create_autocmd({ 'CursorHold', 'CursorHoldI' }, {
      group = group,
      buffer = bufnr,
```

```lua
    vim.notify('All tools present')
    return

  if not args.bang then

      vim.log.levels.WARN

          end

    end

    vim.cmd('MasonInstall ' .. table.concat(mason_pkgs, ' '))
  end

  desc = 'Report missing external tools; :ToolSync! installs them',
})
```

```lua
--- :checkhealth tools — per-language readout of what is present and missing.
--- This is the degradation story for locked-down work boxes: the config never
--- hard-fails on a missing binary, it tells you what you do not have.
local M = {}

function M.check()
  local tools = require('tools').tools
  vim.health.start('External tools')

  local by_lang = {}
  for _, tool in ipairs(tools) do
    by_lang[tool.lang] = by_lang[tool.lang] or {}
    table.insert(by_lang[tool.lang], tool)
  end

  local langs = vim.tbl_keys(by_lang)
  table.sort(langs)

  for _, lang in ipairs(langs) do
    local present, absent = {}, {}
    for _, tool in ipairs(by_lang[lang]) do
      table.insert(vim.fn.executable(tool.bin) == 1 and present or absent, tool.bin)
    end

    if #absent == 0 then
      vim.health.ok(('%s: %s'):format(lang, table.concat(present, ', ')))
    elseif #present == 0 then
      vim.health.error(('%s: all missing (%s)'):format(lang, table.concat(absent, ', ')))
    else
      vim.health.warn(
        ('%s: missing %s'):format(lang, table.concat(absent, ', ')),
        { 'Run :ToolSync! to install' }
      )
    end
  end
end

return M
```

```lua
--- Test running for Java and C++, which have no viable neotest adapter.
--- Deliberately unmagical: build a command line, run it in a terminal split,
--- let the tool's own output be the report.
local M = {}

--- Run `cmd` in a terminal split at the bottom.
---@param cmd string[]
local function run_in_terminal(cmd)
  vim.cmd('botright 15split')
  vim.fn.jobstart(cmd, {
    term = true,
    cwd = vim.fs.root(0, { 'pom.xml', 'CMakeLists.txt', '.git' }) or vim.uv.cwd(),
  })
  vim.cmd('startinsert')
end

--- Nearest enclosing test name, found by walking back for a Java method or a
--- gtest TEST macro. Returns nil when nothing matches.
---@return string|nil
local function nearest_test_name()
  local row = vim.api.nvim_win_get_cursor(0)[1]
  for i = row, 1, -1 do
    local line = vim.api.nvim_buf_get_lines(0, i - 1, i, false)[1] or ''
    -- Java: public void testFoo() / void shouldDoX()
    local java = line:match('%s+void%s+([%w_]+)%s*%(')
    if java then
      return java
    end
    -- gtest: TEST(Suite, Name) or TEST_F(Fixture, Name)
    local suite, name = line:match('TEST_?F?%s*%(%s*([%w_]+)%s*,%s*([%w_]+)%s*%)')
    if suite and name then
      return suite .. '.' .. name
    end
  end
end

function M.test_file()
  local ft = vim.bo.filetype
  if ft == 'java' then
    local class = vim.fn.expand('%:t:r')
    run_in_terminal({ 'mvn', 'test', '-Dtest=' .. class })
  elseif ft == 'c' or ft == 'cpp' then
    run_in_terminal({ 'ctest', '--test-dir', 'build', '--output-on-failure' })
  else
    vim.notify('No file-test command for filetype: ' .. ft, vim.log.levels.WARN)
  end
end

function M.test_nearest()
  local ft = vim.bo.filetype
  local name = nearest_test_name()
  if not name then
    vim.notify('No enclosing test found', vim.log.levels.WARN)
    return
  end

  if ft == 'java' then
    run_in_terminal({ 'mvn', 'test', '-Dtest=' .. vim.fn.expand('%:t:r') .. '#' .. name })
  elseif ft == 'c' or ft == 'cpp' then
    run_in_terminal({ 'ctest', '--test-dir', 'build', '-R', name, '--output-on-failure' })
  else
    vim.notify('No nearest-test command for filetype: ' .. ft, vim.log.levels.WARN)
  end
end

function M.test_all()
  local ft = vim.bo.filetype
  if ft == 'java' then
    run_in_terminal({ 'mvn', 'test' })
  elseif ft == 'c' or ft == 'cpp' then
    run_in_terminal({ 'ctest', '--test-dir', 'build', '--output-on-failure' })
  else
    vim.notify('No test-all command for filetype: ' .. ft, vim.log.levels.WARN)
  end
end

vim.api.nvim_create_user_command('TestNearest', M.test_nearest, { desc = 'Run nearest test' })
vim.api.nvim_create_user_command('TestFile', M.test_file, { desc = 'Run tests in file' })
vim.api.nvim_create_user_command('TestAll', M.test_all, { desc = 'Run all tests' })

-- Java and C++ buffers get the same <leader>t* keys neotest uses elsewhere, so
-- the muscle memory is identical regardless of language.
vim.api.nvim_create_autocmd('FileType', {
  group = vim.api.nvim_create_augroup('config_testcmd', { clear = true }),
  pattern = { 'java', 'c', 'cpp' },
  callback = function(ev)
    local function map(lhs, rhs, desc)
      vim.keymap.set('n', lhs, rhs, { buffer = ev.buf, desc = desc })
    end
    map('<leader>tt', M.test_nearest, 'Test nearest')
    map('<leader>tf', M.test_file, 'Test file')
    map('<leader>ta', M.test_all, 'Test all')
  end,
})

return M
```

```lua
--- gh-dash covers browsing and CI; octo covers line-level review. This module
--- is the thin glue: launching gh-dash and a few `gh run` shortcuts, since octo
--- does not cover GitHub Actions.
local M = {}

---@param cmd string[]
---@param opts? { size?: integer }
local function in_terminal(cmd, opts)
  opts = opts or {}
  vim.cmd(('botright %dsplit'):format(opts.size or 20))
  vim.fn.jobstart(cmd, { term = true })
  vim.cmd('startinsert')
end

--- gh-dash installs two different ways: as a standalone binary (Homebrew) or as
--- a gh extension (`gh extension install dlvhdr/gh-dash`, used by bootstrap.sh
--- on Linux). Those are invoked differently, so resolve whichever is present.
---@return string[]|nil
local function dash_cmd()
  if vim.fn.executable('gh-dash') == 1 then
    return { 'gh-dash' }
  end
  if vim.fn.executable('gh') == 1 then
    local res = vim.system({ 'gh', 'extension', 'list' }, { text = true }):wait()
    if res.code == 0 and (res.stdout or ''):match('gh%-dash') then
      return { 'gh', 'dash' }
    end
  end
end

--- Open gh-dash in a terminal tab, or say why it cannot.
function M.dash()
  local cmd = dash_cmd()
  if not cmd then
    vim.notify('gh-dash not installed — see bootstrap.sh', vim.log.levels.WARN)
    return
  end
  vim.cmd('tabnew')
  vim.fn.jobstart(cmd, {
    term = true,
    on_exit = function()
      vim.schedule(function()
        pcall(vim.cmd, 'tabclose')
      end)
    end,
  })
  vim.cmd('startinsert')
end

function M.runs()
  in_terminal({ 'gh', 'run', 'list', '--limit', '20' })
end

function M.watch_latest()
  in_terminal({ 'sh', '-c', 'gh run watch "$(gh run list --limit 1 --json databaseId -q ".[0].databaseId")"' })
end

function M.failed_log()

end
```

```bash
  fi
```

## Appendix: keymap reference

Leader is `<Space>`.

| Prefix | Domain |
|---|---|
| `<leader>c` | code — format, diagnostics, inlay hints, refactors |
| `<leader>d` | debug — breakpoints, stepping, UI |
| `<leader>f` | find — files, grep, symbols, buffers |
| `<leader>g` | git and GitHub |
| `<leader>t` | test |
| `<leader>x` | quickfix and location list |
| `<leader>D` | database UI |
| `[` / `]` | previous / next — hunk, diagnostic, error |
| `g` | LSP navigation (`gd`, `gD`, `gy`, `grr`, `gri`, `grn`, `gra`, `gO`) |
| `<F5>`–`<F12>` | debug stepping |
| `-` | oil file explorer |
| `s` / `S` | flash jump / flash treesitter |
